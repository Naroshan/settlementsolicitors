# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository reality

This repo does **not** contain buildable source code. It currently holds two identical zip files at the root (`6a4e6adf1949b723bb311fe9-0ceb54adfa4711cd.zip` and `settlementsolicitors-deploy (10).zip`), each a full pre-built static site deploy bundle for **Settlement Solicitors** (settlementsolicitors.com), a trading style of Ackroyd Legal (London) LLP, deployed on Netlify. There is no `package.json`, build tool, or framework config in the repo — the zips are the deployable output itself, ready to be dropped onto Netlify as-is (`netlify.toml` sets `publish = "."`).

To work on the site, unzip one of the bundles (e.g. `unzip "settlementsolicitors-deploy (10).zip" -d site/`) and edit the static files directly. There is no build/lint/test command — changes are made straight to HTML/CSS/JS and redeployed by re-zipping and uploading, or by pushing the raw files if the repo is restructured to serve directly from Netlify.

## Site architecture

- **Static HTML pages**: every route is a real directory with an `index.html` (e.g. `fees/index.html`, `book/index.html`, `settlement-agreements/index.html`), not client-side routed. `404/index.html` is the catch-all 404 page.
- **Programmatic location pages**: `locations/` contains ~117 near-identical city landing pages (one directory per UK city/town, e.g. `locations/london/`, `locations/bristol/`), each with its own `index.html`. These are generated/duplicated pages for local SEO — changes to shared layout/copy need to be replicated across all of them (or generated by whatever tooling produced them, which is not present in this repo).
- **Styling**: `css/style.css` (+ `style.min.css`) is hand-written CSS using custom properties for a cream/forest-green/terracotta color palette, plus Google Fonts (Playfair Display + DM Sans). Pages also inline a compiled Tailwind CSS bundle (`assets/index-*.css`) directly into a `<style id="compiled-css">` tag in `<head>` to avoid a render-blocking request — this Tailwind output is generated elsewhere and only the compiled artifact ships here.
- **JavaScript**: `js/main.js` (+ `main.min.js`) is vanilla JS handling the mobile nav overlay and progressive-enhancement of `form[data-formspree]` forms (AJAX submit to Formspree, replaced with a "Sending…" state). `assets/index-*.js` is a separately built ES module bundle (references `index-DQtTpin4.js`, has JSX-like helpers) powering some interactive widget — also a compiled artifact, not source.
- **Forms**: contact/consultation forms submit to Formspree (`data-formspree` attribute), intercepted by `main.js` for an AJAX experience with a `/thank-you/` redirect page.
- **SEO/metadata**: `sitemap.xml`, `robots.txt`, `llms.txt` (an AI-crawler-facing summary of the firm and its core pages/services), and `_redirects` (Netlify redirect rules for stale URLs, e.g. `/process/` → `/`, `/services/` → `/settlement-agreements/`).
- **Netlify config** (`netlify.toml`): publishes the repo root as-is, sends unmatched paths to `/404/index.html`, and sets security headers (`X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`) plus long-lived immutable caching for `/assets/*`.
